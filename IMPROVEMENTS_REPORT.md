## Parser accuracy, before and after (task 8)

The deterministic parser was measured (`backend/.venv/Scripts/python tests/eval/run_eval.py`). "Exact" means every field is correct.

**The number to quote is 91.7% on the held-out set.** The tuning set was used to find and fix parser bugs, so its 99.2% is optimistic.

| Set | Exact before | Exact after | intent | location | date | parameter | language | climate period |
|-----|-------------:|------------:|-------:|---------:|-----:|----------:|---------:|---------------:|
| **Held-out, 24 queries (headline)** | 41.7% | **91.7%** | 100 → 100 | 62.5 → 100 | 100 → 100 | 83.3 → 91.7 | — → 100 | — |
| Tuning set, 120 queries | 79.2% | 99.2% | 99.2 → 100 | 95.0 → 100 | 99.2 → 100 | 86.7 → 99.2 | 99.2 → 100 | 84.6 → 100 |

Per language on the tuning set:

| Language | Exact before | Exact after |
|----------|-------------:|------------:|
| English | 70.0 | 100 |
| Hindi | 85.7 | 100 |
| Hinglish | 89.3 | 96.4 |
| Marathi | 75.0 | 100 |

- **How to read this:** the held-out set was written after tuning and scored once, with no changes afterwards. The tuning set is the one the parser was fixed against, so its scores are optimistic.
- **Raw reports:** `tests/eval/results_{before,after,heldout,heldout_before}.json`.
- **Misses left visible:**
  - "hawa kitni tez" ("how strong is the wind") is read as `strong_wind`; my label is `wind`.
  - My labels are inconsistent for "maximum temperature" between English and Hindi in the held-out set.
  - Marathi "पूर" (flood) is not yet a heavy-rain word.

## Needs your input

1. **Web Push setup.** `pywebpush` is installed and pinned. To send pushes:
   - generate VAPID keys and set `VAPID_*` (`docs/EARLY_WARNING.md`, step 2)
   - set `SUPABASE_SERVICE_ROLE_KEY` and `ALERT_JOB_TOKEN`
   - schedule the job (step 5)
2. **Supabase:** run `supabase/migrations_6_7.sql` in the SQL Editor. It adds `profiles.role` and `alert_subscriptions`, and its last statement prints a check.
3. **Restart the backend** and run `pip install -r requirements.txt` to pick up `pywebpush`.
4. **Untested end to end:**
   - signed-in push subscribing (no test Supabase account)
   - a real push delivery to a browser (sending is tested with HTTP mocked)
   - real-device speech recognition for mr-IN (e2e uses fakes)
5. **Still in English:** the weather description on the answer panel, the aviation panel, and the dashboard and map pages. These follow the UI, not the reply. Chat replies are fully translated.
6. **E2E and your dev server:** with `npm run dev` running, the parallel Playwright run can become CPU-starved and WebGL-heavy tests time out. Use `npx playwright test --workers=1` while the dev server runs, or stop it first.
7. **Scope notes:**
   - There is no WRF source; WRF questions get GFS.
   - The Indian AQI is computed from modelled PM, not read from CPCB stations, and replies say so.
   - The smart-city feature is only partial.
