### See a real test notification

1. Start the backend with the venv active (`cd backend; .\.venv\Scripts\Activate.ps1; uvicorn main:app --port 8000`). `GET http://localhost:8000/api/push/config` must say `"available": true`.
2. Start the frontend (`cd weathergpt-web; npm run dev`) and open `http://localhost:3000` in Chrome or Edge. Push needs `localhost` or HTTPS.
3. **Sign in** with a real Supabase account (top right → Sign in). Demo mode has no account and cannot subscribe.
4. Open **Alerts** and pick a location ("Use my current location", or type a city).
5. In **Push alerts**, tap **Alert me for …** and allow notifications when the browser asks. The place appears in the list under the button.
6. Tap **Send test alert**. Within a few seconds the OS shows "WeatherGPT test alert: TEST: WeatherGPT demo alert, not an official IMD warning", and the panel says "Test alert sent". Clicking the notification opens `/alerts`.
7. A second tap within a minute says "One test per minute". If it says the alert could not be delivered:
   - check that notifications for `localhost` are allowed in the browser and in Windows (Settings → System → Notifications);
   - then tap **Alert me** again.

### Why CI failed (and passed locally)

`gh run view 41492637577 --log-failed`: backend tests, eslint, build and the Chromium install pass. Playwright gave **116 passed, 4 failed**, all on the desktop home page:
- a11y keyboard test
- D-panel scenes
- console placeholder
- Marathi aviation panel

The pattern: `locator.evaluate` hung for 60 s on an element that was already visible, and panels that render in milliseconds never appeared. **The page's main thread was blocked.**

**Cause.** Headless Chromium has no GPU, so WebGL runs on **SwiftShader**, on the CPU. This happens on the GitHub runner and on this laptop too: the probe reports `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero)))`. The animated three.js sky at 1440×900 then competes with React for the CPU. On this machine it was borderline: one single-worker run failed the same a11y test. The slower runner fails every time.

**Fix (product, not test).**
- `lib/liteMode.ts` auto mode now also turns on lite mode when WebGL is drawn in software (SwiftShader, llvmpipe, softpipe, Microsoft Basic Render Driver), as it already did for ≤2 cores or ≤2 GB.
- Real users on PCs without graphics acceleration hit the same software path. This was measured only in headless Chromium, not on such a PC. They now get the CSS sky, and the toggle says why: "no graphics acceleration".
- A manual "off" still forces the WebGL sky, so the lite-mode test still exercises it.
- No assertion was changed.
- New e2e test: a faked SwiftShader renderer string turns lite mode on.

**Consequence for tests.** Desktop e2e now runs the CSS sky. WebGL rendering is covered by the lite-mode test (manual "off"), and visually by the screenshot run on a machine with a GPU.

The earlier suspects were checked and ruled out:
- eccodes / eccodeslib wheels: the backend job passes on 3.11;
- timezone and locale: the full suite passes with `timezoneId: 'UTC'`, `locale: 'en-US'`;
- missing files: nothing needed is untracked.

### What the hazard map does

- **`GET /api/map/hazard`.** Returns the level per H3 cell for the 24 h from the slider hour (0–48).
  - **Resolution, honestly.** Res 6 hexes are 6.5 km across (36 km²). That is the closest size to the ~8 km (64 km²) model cell that is not coarser, so a hex never claims more detail than about one model cell. Res 5 (17 km) would merge about four model cells.
  - **Zoomed out**, samples are further apart, so the resolution drops to the finest hex at least 0.7 × the sample spacing.
  - **Values.** Each hex takes its nearest sample's values. Nothing is interpolated for hazards.
- **`GET /api/map/hazard/summary`.** Returns, within 25 km: cells per level, the most rain, the worst cell now, and the first window at the worst level in the next 72 h.
- **One scorer (`backend/alerts/scoring.py`).** The alert engine (so `/api/alerts`, the risk board, push and CAP) and the hazard map all call it. Hour 0 includes the model's current values, exactly like alerts.
  - `tests/test_hazard.py` runs 17 scenarios through the same mocked Open-Meteo data, covering every level and every hazard.
  - For each, alerts, the risk board, the push level, the summary and the place's hex must agree on every hazard. They do.
- **Levels: none < advisory < watch < warning < severe.**
  - The **severe** rules use published bounds, cited in `thresholds.py` and `docs/EARLY_WARNING.md`:
    - IMD "very heavy rainfall": 115.6 mm in 24 h
    - IMD severe heat wave: 47 °C
    - Beaufort 10: 89 km/h
    - WMO 99: thunderstorm with heavy hail (96 stays a warning)
  - **Heat stress** uses the NWS heat-index bands: Danger is a watch, Extreme danger a warning.
- **Map.**
  - A **Hazard** layer with type chips: all, rain, heat, wind, thunderstorm, cold.
  - **Tapping a hex** (or "Weather at map centre") shows the level, each triggering value vs its threshold ("45 mm ≥ 15 mm"), the window, the facts, and "estimated · model grid ≈ 8 km · not official IMD".
  - The **72 h slider** moves the window.
  - A **summary panel** ("Within 25 km of Pune: 3 warning cells, most rain 72 mm, worst in 4 h") with **Show me the worst**, which flies there and sets the hour.
- **Roads like traffic colours.**
  - **Source.** Lines come from the basemap's own `transportation` vectors: motorway and trunk when zoomed out, then primary, then secondary. Each road is cut where it enters a new cell and takes that cell's level. Nothing is drawn outside the data.
  - **Readability.** A dark casing goes under every road, and a light one under severe roads so dark red stays visible.
  - **Cost control.** A 30,000-vertex budget, recomputed only when the view, hour or type changes.
  - **Legend.** It reads "Road colour = weather hazard on that road. It is NOT traffic."
- **Four languages.** The chips, legend, card, summary, the new rule names and the threshold windows are in all four (the windows used to show in English everywhere).
- **Reduced motion and lite mode.** Fly-tos don't animate. Hazard mode has no particles in any mode, because they hid the levels.

### Behaviour changes to know about

1. **Alert windows start at the current hour.** The engine's "next 24 h" used to be the first 24 entries of Open-Meteo's series, which starts at local midnight. In the evening, that was mostly the past. Alerts and the risk board's 24 h numbers now use the 24 h from the current hour.
2. **Traffic colours on every surface.**
   - Advisory was blue and is now yellow. Watch is orange, warning red, severe dark red.
   - Adjacent levels pass the dataviz validator's normal-vision (16.2) and colour-blind (12.2) separation on the map surface. Severe is below 3:1 there, so it always has a light outline or its word.
   - The text shades still pass `e2e/contrast.spec.ts` over every sky. Severe text needed red-100.
   - The risk board's map now reads the tokens instead of hard-coded hex values.
3. **Push escalation.** Push now also fires when a warning escalates to severe, and still never repeats at the same level. CAP maps severe to "Extreme".

### Community reports

- **Kinds:** waterlogging, fallen tree, landslide, hail, heavy rain, strong wind, road blocked; optional note (280 characters) and photo.
- **Safety:** sign-in (verified with Supabase Auth), 1 a minute and 5 an hour, 6 h on the map (24 h for landslide and road blocked), 3 flags hide a report, one vote per person, never on your own report. The reporter's id never leaves the server; the card says "a resident" and a time rounded to 10 minutes.
- **Storage:** `community_reports` and `report_votes` are private (RLS on, no policies, no grants); only the backend writes them, with the service-role key. Photos sit in a private bucket and are served by the backend.
- **Photos:** Pillow decodes and re-encodes every photo as a new JPEG (≤ 1600 px): EXIF incl. GPS and all other metadata are gone (tested with a real GPS-tagged JPEG), the camera's rotation is applied first, 8 MB and 40 MP guards. The browser converts HEIC (and other formats it can decode) to JPEG; anything else gets "Please use a JPEG or PNG photo".
- **Trust:** `0.35 model + 0.25 nearby + 0.15 age + 0.25 reporter − 0.1 per flag`; Low < 0.4 ≤ Medium < 0.65 ≤ High. The model part is one Open-Meteo call when the report is made; its bands (AMS rain rates, the alert wind rules, the 24 h rain rules) are in `thresholds.py`.
- **Never** a forecast number or an alert level: a test checks that no forecast, alert, route, risk-board scoring or push module imports `reports`.

### Waterlogging risk (experimental)

`score = min(1, R × (0.4 + 0.6 L) + 0.3 C)` per ~1 km hexagon: R from rain over the past 3 h and next 6 h, L from metres below the two rings around (AWS terrain tiles, decoded with Pillow), C from nearby waterlogging reports by trust. No rain and no reports means no risk. Limits are on the map and in `docs/WATERLOGGING.md` (8 km rain, 76 m terrain, no drains, pumps or tides).
