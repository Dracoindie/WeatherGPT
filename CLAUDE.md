# WeatherGPT: context for Claude Code sessions

SIH 2026, problem statement **SIH26068**: a conversational, multilingual weather platform for India, with real-time and forecast data, NWP (GFS), extreme-weather alerts with early-warning dissemination, climate trends, and role-specific advisories. It is mobile-first.

Start here, then read `README.md` (API reference) and `IMPROVEMENTS_REPORT.md` (what was built, accuracy numbers, open items).

## Ground rules (do not break these)

1. **The LLM is never the source of weather facts.** The pipeline is:
   `Open-Meteo / GFS / archive → Pydantic validation → WeatherFacts (or ClimateFacts / NwpFacts) → language layer`.
   - Templates in `backend/llm/response_generator.py` and `backend/llm/source_replies.py` are the default.
   - An optional LLM only rewords. Its output is rejected unless every number appears in the facts or advisory reasons. The check is `is_grounded` / `numbers_grounded`.
   - Role notes (`roles/notes.py`) use only facts values, so they pass the check by construction.
   - **Any new reply text must pass the grounding check.** Add a test for it.
2. **Alerts are WeatherGPT's, not IMD's.** Every alert surface says "Generated by WeatherGPT, not official IMD warnings": the UI, `/api/alerts` `note`, push text, WhatsApp share and CAP.
3. **Never hardcode city coordinates.** Places are geocoded (Nominatim, cached 24 h, at most 1 request/second).
4. **Location priority in chat:**
   1. place named in the message
   2. request GPS coordinates
   3. conversation context
   4. trusted Supabase profile default (JWT-verified; RLS)
   5. ask for a city (HTTP 200, not 400)

   If the geocoder is down, reply in the user's language with HTTP 200, not a 502.
5. **Replies are in the user's language:** `en`, `hi` (Devanagari), `hinglish` (romanised), `mr` (Marathi).
   - New user-facing text needs all four.
   - WMO descriptions are translated in `llm/weather_codes.py`. The UI uses `weathergpt-web/lib/i18n/weatherCodes.generated.ts`, generated from it by `backend/llm/export_weather_codes.py` (a test fails if it is stale). Use `useDescribeWeather()`; never add another description table.
   - The API's `weather_description` and the `advisory` object stay English.
6. **Secrets stay out of git.**
   - All env files are git-ignored except `*.example`.
   - Never commit `VAPID_PRIVATE_KEY`, `SUPABASE_SERVICE_ROLE_KEY` or `ALERT_JOB_TOKEN`, and never put them in `NEXT_PUBLIC_*` variables.
7. **Dependencies are pinned** (`backend/requirements.txt`). Ask before adding one.

## Architecture

```
weathergpt-web/ (Next.js, "Living Sky" UI)  ──HTTP──▶  backend/ (FastAPI, port 8000)
   Supabase auth (browser)                              ├─ Open-Meteo forecast / archive / air quality
   service worker: offline last forecast, Web Push       ├─ NOAA NOMADS GFS 0.25° (cfgrib)
                                                         ├─ Nominatim geocoding
                                                         └─ Supabase REST (profiles, alert_subscriptions)
```

### Backend (`backend/`, Python 3.11, FastAPI, Pydantic v2, httpx)

| Path | What it does |
|------|--------------|
| `main.py` | App, CORS (`ALLOWED_ORIGINS`), routers, `/health`, `/api/weather`. `/api/nwp` is skipped with a 503 stub if cfgrib or ecCodes is missing. |
| `api/chat.py` | `POST /api/chat`: parse → follow-up context → resolve location → route by intent (forecast / climate / nwp) → facts → advisory → reply + role note |
| `llm/query_parser.py` | Intent, place, date, parameter, language and climate period. An optional LLM parser, with a deterministic fallback (the benchmark measures the fallback). |
| `llm/follow_up.py` | Fills missing slots from `ChatRequest.context` ("aur parso?", "what about Mumbai?") |
| `llm/response_generator.py` | Templates in 4 languages, the grounding check, `ask_for_location`, `unknown_location`, `geocoder_unavailable` |
| `llm/source_replies.py` | Climate and GFS reply templates |
| `llm/weather_codes.py` | WMO code descriptions in hi / hinglish / mr |
| `llm/provider.py` | `LLM_PROVIDER` = gemini, groq, openai or none |
| `query_service.py` | Open-Meteo to `WeatherFacts`: period windows in the location's local time, `focus_facts` per parameter, English `WMO_DESCRIPTIONS` |
| `weather/open_meteo.py` | Forecast client (current + 7-day hourly) |
| `geocoding.py` | Nominatim search and reverse, TTL cache and rate limit. Raises `RuntimeError` when the service is down; returns `None` for an unknown place. |
| `thresholds.py` | **The one table of hazard thresholds and levels.** Engine, chat advisories, risk board, push, CAP and `GET /api/alerts/thresholds` all read it. Never hard-code a threshold elsewhere (UI included). |
| `advisory.py` | Chat advisory from `thresholds.py`, plus localised advisory text |
| `alerts/engine.py` | Alert engine (advisory / watch / warning). `api/alerts.py` retries, serves stale data, then returns a clean 503. |
| `climate/` | Open-Meteo archive: a period compared with the same dates over the previous 10 years |
| `nwp/` | GFS from NOMADS via the GRIB filter. Decoding runs in a worker thread. |
| `maps/` | `/map` data: `point.py` (tapped point: shared Open-Meteo client + CAMS AQI + heat index, 10 min cache), `grid.py` (up to 100 points in ONE Open-Meteo request, 72 h, snapped step ladder, 15 min cache, `MODEL_GRID_KM`), `heat_index.py` (NWS method; bands in `thresholds.py`) |
| `air/` | Open-Meteo CAMS PM2.5/PM10 to Indian AQI (CPCB breakpoints), plus UV |
| `roles/` | `farm.py`, `aviation.py`, `risk.py` (district board), `compare.py` (GFS vs Open-Meteo), `notes.py` (one role sentence per reply) |
| `dissemination/` | `push.py` (pywebpush + VAPID), `job.py` (push only when severity becomes `warning`), `store.py` (Supabase service role), `cap.py` (CAP 1.2 XML), `demo_push.py` (signed-in test push; never writes `last_severity`) |
| `auth/trusted_location.py` | Verifies the Supabase JWT, then reads `profiles` (`id=eq.<sub>`, RLS) |
| `http_tls.py` | Shared TLS context for all HTTP clients |
| `env_check.py` | Startup warning when only `NEXT_PUBLIC_` Supabase names are set (never used as a fallback) |

**Endpoints:**
- `/api/chat`, `/api/weather`, `/api/forecast`, `/api/alerts`, `/api/alerts/thresholds`, `/api/alerts/cap`, `/api/climate`, `/api/nwp`
- `/api/map/point`, `/api/map/grid`
- `/api/air-quality`, `/api/farm`, `/api/aviation`, `/api/risk`, `/api/compare`
- `/api/push/config`, `POST /api/alerts/check` (needs the `X-Job-Token` header), `POST /api/push/test` (signed-in demo push to the caller's own subscriptions, 1/min)

### Frontend (`weathergpt-web/`, Next.js 16, TypeScript, Tailwind, react-three-fiber, MapLibre GL + deck.gl, Leaflet)

- **This Next.js has breaking changes compared with training data.** Read `weathergpt-web/AGENTS.md` and `node_modules/next/dist/docs/` before writing Next code. It uses `proxy.ts`, not `middleware.ts`.
- **Pages** (`app/`):
  - `/`: the Living Sky chat console, with a 3D sky scene driven by real codes and wind
  - `/dashboard`, `/alerts`, `/climate`, `/map`, `/disaster` (district board), `/login`, `/signup`, `/offline`
  - `/map` is `components/map3d/` (MapLibre GL + deck.gl, loaded only there). Basemap: OpenFreeMap `dark` style; terrain: AWS terrarium tiles; both keyless. MapLibre's worker is copied to `public/vendor/` by `scripts/copy-maplibre-worker.mjs` (`predev`/`prebuild`, git-ignored). Broadcast mode renders through a portal on `<body>`; the map container node is moved, never rebuilt. Map colours are the `--map-*` tokens in `globals.css` (validated one-hue ramps). Every map shows "Model grid ≈ 8 km · estimated · not official IMD". Roadmap: `docs/VISION.md`.
- **Shared code:**
  - `context/`: `I18nContext` (UI dictionary: EN / हि / Hinglish / मरा), `AuthContext`, `DemoContext`
  - `lib/api/`: backend clients
  - `lib/push.ts`, `public/sw.js`: Web Push and offline cache
  - `lib/voice/`: speech recognition and synthesis in en-IN, hi-IN and mr-IN
  - `lib/liteMode.ts`: automatic lite mode
  - `components/ui/`: the design system (`AppShell`, `PageHeader`, `SeverityBadge`, `SkyButton`, `SkyInput`; `GlassPanel` lives in `components/panels/`)
  - `lib/format.ts`: human-friendly dates, windows, sources and m/s→km/h
  - `lib/useLocationWeather.ts`: weather, forecast and alerts for a picked place (dashboard and map)
  - `lib/gridFill.ts`: balanced panel grids with no holes
- **PWA:** `app/manifest.ts` and the service worker. The mobile layout has a bottom nav and a docked console, with no horizontal scroll at 390 px.
- `weathergpt-web/` was imported with `git subtree`. It is a normal folder in this repo, not a submodule.

### Data sources

| Source | Used for | Key |
|--------|----------|-----|
| Open-Meteo forecast | Current conditions and 7-day hourly (temperature, rain, probability, wind and direction, gusts, humidity, visibility, cloud, UV, WMO code) | none |
| Open-Meteo archive | Climate trends (10-year baseline) | none |
| Open-Meteo air quality (CAMS) | PM2.5 and PM10, giving the Indian AQI. This is modelled, not CPCB station data, and replies say so. | none |
| NOAA NOMADS GFS 0.25° | The NWP chat intent and the researcher comparison. There is no WRF source; WRF questions get GFS. | none |
| Nominatim (OSM) | Geocoding and reverse geocoding | none (User-Agent, 1 request/s) |
| Supabase | Auth; `profiles` (default location, `role`); `alert_subscriptions` | anon key, plus the service-role key for the job only |

### Roles (`UserRole`: `citizen`, `farmer`, `aviation`, `disaster_manager`, `researcher`)

The role is sent in `ChatRequest.role` and saved in `profiles.role` (migration 6). **A role changes what a reply emphasises, never the numbers.**
- **citizen:** plain replies
- **farmer:** spray, irrigation, harvest and sowing windows. Thresholds are in `docs/ROLE_ADVISORIES.md` and `roles/farm.py`.
- **aviation:** a briefing with visibility, clouds, wind and gusts in knots, and flags. It is not a METAR or TAF.
- **disaster_manager:** a district risk board sorted by severity (`/disaster`), push alerts and CAP export
- **researcher:** GFS vs Open-Meteo bias and MAD, climate anomalies and the parser benchmark

### Database (`supabase/`)

- `schema.sql` is the full schema: sections 1–5, then migration 6 (`profiles.role`) and migration 7 (`alert_subscriptions` + RLS). It is idempotent.
- `migrations_6_7.sql` contains only 6 and 7, for a database that already has 1–5. Keep it in sync with `schema.sql`.

## Design rules (one design: Living Sky)

Every page must look like it belongs to the Living Sky home. Before adding UI, reuse what exists.

1. **Shell.** Every route renders inside `<AppShell>` (`components/ui/AppShell.tsx`). It gives the sky background, the one nav (`SkyNav`), the bottom nav and the page padding. Never add another nav or header.
2. **Background.** Inner pages use the CSS `StaticSky` (no WebGL); call `useSkyFromCurrent(current, timezone)` when the page has current weather. Only `/` runs the WebGL scene. The sky must cover the full page height (it fades into `--sky-floor`).
3. **Tokens, not hex.**
   - Text is `text-hud` / `text-hud-dim`, and lines are `border-white/10`.
   - **Strong colours are for fills, borders, dots, glows and map markers:** `bg-accent`, `border-accent`, `--sev-none | advisory | watch | warning | unknown` (Tailwind `bg-sev-*` / `border-sev-*`, or `SEVERITY_VAR` for inline styles).
   - **Text and icons in a severity or accent colour use the lighter text shades:** `text-accent-text`, `text-sev-*-text`, or `SEVERITY_TEXT_VAR`. The strong red is about 2.2:1 as text on glass over a daytime sky; the text shades stay at 4.5:1 or more over every sky phase. `--sky-accent-text` follows the severity state (cyan → amber → rose).
   - `e2e/contrast.spec.ts` computes these ratios from the live tokens and the real sky palette (`PALETTES` in `lib/weatherScene.ts`), and fails on `text-sev-<level>` without `-text`, on `text-accent`, and on inline `color: SEVERITY_VAR`. axe can't measure text over the sky gradient, so this spec is the contrast check.
   - Do not use the old light classes (`bg-panel`, `text-ink`, `teal`, `coral`): they are aliases kept only for safety.
4. **Components.**
   - Surfaces are `GlassPanel` (or the `.sky-glass` class), with the label in `.sky-label`.
   - Buttons are `SkyButton` / `SkyLinkButton` (`primary | ghost | subtle`), and inputs are `SkyInput` / `.sky-input`.
   - Page titles use `PageHeader`.
   - Severity is shown with `SeverityBadge`.
   - Use `LocationPicker` for places.
5. **One chat.** The chat is the Living Sky console. Other pages link to it with `askHref(question, coords)` (`/?q=…&lat=…&lon=…`); never embed a second chat box.
6. **One source of truth for warnings.**
   - The location status is `AlertBanner`, fed by `/api/alerts`.
   - Thresholds come from `backend/thresholds.py` via `/api/alerts/thresholds`; never hard-code a threshold in the UI.
   - Chat advisories are labelled with their period.
7. **Units and formatting.**
   - km/h for wind everywhere. Convert m/s with `msToKmh`.
   - Never show raw ISO timestamps or raw source ids. Use `formatDay`, `formatLocalTime`, `formatWindow` and `formatSource` from `lib/format.ts`.
   - Weather descriptions come from `useDescribeWeather()`.
8. **Layout.**
   - Grids must have no holes at 390, 768 and 1440 px. For conditional panels, use `lib/gridFill` (`panelSpanClasses`).
   - No horizontal page scroll at 390 px: wide tables scroll inside their panel or switch to a vertical layout.
   - Nothing important may be truncated mid-word; prefer wrapping or an ellipsis with `title`.
9. **Language.** All new UI text goes in the `I18nContext` dictionary in all four languages (en, hi, hinglish, mr). Use `fill()` for `{placeholders}`.
10. **Charts.** Load the dataviz skill first.
    - One y-axis per chart: different units get separate charts.
    - Validate series colours against the dark surface.
    - Hover and focus tooltips; a table view behind a toggle.
11. **Check it.**
    - After any UI change, run `AUDIT_DIR=screenshots/wip npx playwright test e2e/audit.spec.ts` and look at the images at both widths before committing.
    - `e2e/design-system.spec.ts` and `e2e/home-layout.spec.ts` guard the shell, nav, grid and truncation rules.

**Test notes:**
- Playwright mocks the backend, Nominatim and Supabase (`e2e/support/mockApi.ts`).
- If `npm run dev` is also running, use `--workers=1`, or WebGL-heavy tests may time out.
- Headless Chromium draws WebGL in software (SwiftShader), so lite mode's auto setting picks the CSS sky in e2e (`lib/liteMode.ts`, reason `software-renderer`). That is the CI fix. A test that needs the WebGL sky sets `localStorage['wgpt:lite-mode'] = 'off'`, as the screenshot and audit specs do.
- Demo replay for offline judging: `docs/DEMO.md` (`DEMO_REPLAY=1`, fixtures in `backend/data/demo_fixtures/`).
- On Windows, set `PYTHONIOENCODING=utf-8` when printing Devanagari from Python.
